迷路メーカー

卒業制作 / チーム制作（担当：マップエディタ・当たり判定システム・CSV管理）

概要

3D迷路ゲーム制作を効率化するために 開発したマップエディタです。 ブロック配置だけでなく、 レイヤー編集・CSV保存読込・ 当たり判定管理まで行えます。 現在も機能追加を続けています。

実装機能

  • マウスによるブロック配置
  • レイヤー切替編集
  • CSV保存・読込
  • ブロック回転機能
  • 当たり判定編集
  • ゲーム側とのデータ共有
  • マップ一覧管理
  • リアルタイムプレビュー

使用技術

  • C++
  • DxLib
  • CSVデータ管理
  • 3D座標計算
  • シーン管理
  • 当たり判定システム
  • CSVを利用したデータ駆動設計
    model_config.csv や collision_config.csv を読み込み、 モデル情報や当たり判定情報を外部データとして管理しています。 新規オブジェクト追加時にコード修正を最小限に抑えられる構造にしました。
  • 独自マップフォーマットの実装
    FLOOR・WALL・CORNER・DECO・EVENTなどをセクション分割した CSVフォーマットを設計し、 エディタとゲーム本体で共通利用できるようにしています。
  • 多層マップ管理システム
    3次元配列による階層管理を行い、 プレイヤーの高さから現在階層を自動判定する仕組みを実装しています。
  • 拡張可能な当たり判定システム
    通常のセル単位判定だけでなく、 辺ごとの当たり判定・厚み変更・長さ変更・コーナー判定を実装。 マップごとに細かなコリジョン調整が可能です。
  • 階層単位ロードによる最適化
    現在の階層のみを描画・判定対象にすることで、 マップ規模増加時の負荷軽減を意識して設計しています。
  • 責務分離を意識した設計
    描画処理・移動判定・カメラ判定を別ファイルへ分割し、 機能追加や保守を行いやすい構成にしています。

ポケAPI タイピングゲーム

個人制作 / 制作期間：2週間

概要

PokéAPIを利用し、ランダムに取得したポケモン名を ローマ字入力でタイピングするゲームです。

単なる文字列一致ではなく、 状態遷移型ローマ字判定エンジンを独自設計し、 複数入力候補を同時に保持しながら 正誤判定を行う仕組みを実装しました。

技術的特徴

  • 状態遷移型ローマ字判定エンジン（Listによる分岐管理）
  • 「shi / si」「tsu / tu」など複数入力候補の同時追跡
  • 拗音（キャ / シャ）・促音（ッ）対応の2文字先読み処理
  • GASを利用したオンラインランキング送受信機能
  • 仮想キーボード連動によるリアルタイム入力可視化

スクリプト構成・処理内容

  • PokeApiManager.cs
    ランダムIDを生成し、APIからJSONデータを取得。
    取得データを整形し、問題用ポケモン名と画像を生成。
  • TypingEngine.cs
    List<State>を用いた状態遷移型入力判定を実装。
    入力ごとに候補を絞り込み、 分岐入力を許容しながら正誤判定を行う。
  • RankingManager.cs
    GASへPOST送信しスコアを保存。
    mode=getでランキング取得後、 スコア順に並び替えて表示。
  • UIController.cs
    入力状態に応じて文字色を変更し、 次に押すべきキーをガイド表示。

工夫した点

  • 単純一致ではなく「入力状態管理型エンジン」として設計
  • 複数候補を同時保持することで柔軟な入力対応を実現
  • 非同期通信時のエラー処理を実装し安定性を確保
  • 入力ミス時の演出を追加し、ゲーム体験を向上

恐怖の館 C++版

個人制作 / 制作期間：2週間

技術概要

  • DxLibを使用した自作3Dレイキャストによる壁描画
  • BFS/A*を用いたグリッドベースの敵AI追跡
  • プレイヤー心理演出（恐怖値・心拍UI）

スクリプト抜粋・見せたい部分

// 3Dレイキャストによる壁描画
for (int x = 0; x  SCREEN_W; x++) {
    float rayAngle = angle - FOV / 2 + (float)x / SCREEN_W * FOV;
    float distance = CastRay(rayAngle);
    DrawWallColumn(x, distance);
}

// 敵AI：BFSによる追跡
if (chasing) {
    FindPathBFS(exTile, eyTile, pxTile, pyTile, path);
    MoveEnemyAlongPath(path);
}

// 恐怖値と心拍UI
DrawBox(50, 650, 50 + (int)(fear * 2), 670, GetColor(255, 0, 0), TRUE);
if (fear > 50 && heartBeatTimer > 30) {
    HeartBeatEffect();
}

工夫した点

  • レンダリングとAIを分離し、パフォーマンスを最適化
  • 経路探索は一定間隔で再計算しCPU負荷を抑制
  • 恐怖値や心拍UIによりプレイヤー体験を強化
  • 「プレイヤーが迷わず体験できる設計」を意識
